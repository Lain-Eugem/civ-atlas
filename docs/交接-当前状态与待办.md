## 3. 数据模型：地块到底是怎么分的

这是你问的核心，先讲清楚"地块"有三层，不要把三层混为一谈：

| 层 | 名字 | 数据结构 | 规模（seed 7 / cells=12000） | 谁在用 |
|---|---|---|---|---|
| 1 | 网格地块 **cell** | `world.mesh`：球面 Delaunay 三角网，`x/y` 是等距圆柱主图坐标，`adjStart/adj` 是邻接表，`triangles` 铺满整球 | **n ≈ 34,043** 个 cell，`triangles = 2n−4` | 地形栅格化、河流、生物群系 |
| 2 | 州 / 地区 **region** | `civ.regions`：`count`、`cellStart/cells`（每个州含哪些 cell）、`of[cell]`（cell→州）、`biome`、`adj` | 数百个州（每年可能变） | 人口、经济、战争、归属 |
| 3 | 国家 **polity** | `civ.polities[]`，`civ.polity[region]` 给出每个州的宗主 | 几十到几百 | 疆域填色、外交 |

- 地图平面固定 `2048×1024`（`world.width/height`，等距圆柱），纬度 90°…−90°，经度 −180°…180°，东西相连、跨极镜像。
- **地块边界不是方格**，是三角网；但三角网在 2048 宽的图上非常细（spacing ≈ 12–14 px），单看一个 cell 近似一个小多边形。
- 州是把相邻 cell 合并成的连通块；**国的边界理论上应该落在州界上**，州界又大体沿山脊、大河、海岸走——这就是原版疆域看起来"沿地形"的原因。

## 6. 错误与未解决问题

### E1（最重要）河流：一直没有复现原版
- 现象：我们画的河在 1× 下像短棒/断头，放大后形状又变；用户两次否掉。
- 根因（已查实）：
  1. `fantasyFullPixels`（我们唯一复用的整图像素入口）**根本不画河**；回退后整图河色像素 = 0。
  2. 原版的河在 `src/render/fantasy.ts:1082 fantasyVectorParts()` 的第 2 个 part：`drawRivers(ctx, world.rivers, v, world.riverThreshold, fantasyRiverStyle(v.k, threshold))`（`:1091/:1098`），是**浏览器 canvas 上的矢量层，按当前缩放 k 现算**。
  3. 我们把它当"位图里的一层"烘进底图/瓦片，只能靠水陆掩膜近似裁端点；再叠加预渲染，就彻底失去"随缩放"的能力。
- 状态：**已回退，当前无河**。正确做法见 7.1。

### E2（最重要）疆域：小方块、越海、边界不清
- 现象：开"国家填色"后是一堆聚集、杂乱、无清晰边界、甚至压在海上的小方块。
- 根因（已定位到行）：
  1. `mcp/viewer.ts:402 renderOwnerMap()` 先用 `stampCells()`（`:299`）在**每个有主 cell 的中心盖一个半径 `spacing*0.55` 的实心方块**（`stampRadius` 在 `:426`）。方块不判水，所以海边/岛上会压到海里；方块之间重叠，看起来就是"聚集的小方块"。
  2. 方块之上再补"三个顶点同属一国"的三角形（`:433-455`），只补内部，**边界三角形被跳过**，于是边缘只剩方块、内部是三角面，两种画法拼在一起 → 杂乱、锯齿、空洞。
  3. 颜色来自 `civ.polities[id].color`，整体 alpha 172（`:457-460`）直接盖在地形上，没有"贴边浓、往里淡"，也没有国界线。
- 状态：**未修**。正确做法见 7.2。

### E3 瓦片之间的色调差
- 跨倍率时相邻瓦片有 2–3 级 RGB 的竖缝，根因是 `alignColors` 用 32px 分块做低频对齐（近似）。影响观感，不影响正确性。

### E4 冰缘线在高倍率有台阶
- 冰缘折线来自 **1× mask**（`seaIceField` 的判据），2× 以上沿 1× 走线会有台阶感；要更细需按 S 重算 mask（成本高）。

### E5 预渲染耗时与覆盖面
- 672 块（S=2/4/8 × layer 0）首次 **195–215 s**、磁盘 **235 MB**；第二次同 worldId **0 s**。
- 只预热**建世界时那一种画法**（默认 `fantasy`）的 layer 0；换画法、跨极镜像层（layer 1）仍需现算。
- 世界对象只存在查看器进程内存里：**重启查看器后 worldId 失效**，要重新建世界（同 seed 会命中磁盘瓦片，很快）。

### E6 进程管理坑（Windows）
- `Get-Process node | Where { $_.CommandLine -match 'viewer.js' } | Stop-Process` **不可靠**（CommandLine 常为空），旧进程会继续占着端口返回旧缓存，让人误以为"改了没生效"。
- 正确：`Get-NetTCPConnection -LocalPort 5191 -State Listen | % { Stop-Process -Id $_.OwningProcess -Force }`。

### E7 缓存版本双 bump
- 改底图像素 → `MAP_VER`；改瓦片像素 → `TILE_RENDER_VER`；改矢量 JSON 结构 → 不用 bump，但查看器进程内的 `vectorCache`（`mcp/viewer.ts:616`）要重启进程才刷新。

## 7. 两件待办的正确做法

### 7.1 河流：做成"独立的矢量图层，随缩放现算"

**不要**再烘进底图/瓦片，**不要**用 2× 水陆掩膜逐像素裁。

上游已经把这件事拆好了，直接复用：

- `src/render/common.ts:453` `export function drawRivers(ctx, rivers, at: number | VecView, threshold, style, opts?)`
  - `at` 给数字 = 整张图的像素倍数（烘进底图用）；给 `VecView` = 屏幕坐标现画。
  - `VecView`（`common.ts:263`）是 `{ s, ox, oy, k, wrap? }`：`s` = 一个世界单位多少画布像素（≈ 缩放倍数），`ox/oy` = 平移，`wrap` = 世界宽度（东西相连时伸出左右边的河在另一边再画一份）。
  - 河流线宽、分段平滑、`minFlux` 过滤、画布外裁剪，全在这个函数里（`common.ts:471-520`），`ctx.canvas.width/height` 就是视口。
- 河的风格（原版手绘风）在 `src/render/fantasy.ts:3546`，是**模块私有**函数，没有 export，照抄这 6 行即可：
  ```ts
  const kk = Math.max(1, k);
  { color: 'rgba(48,82,110,0.9)', minW: 0.5, maxW: 0.5 + 1.5 * Math.pow(kk, -0.2),
    fluxRef: 900, thin: Math.pow(kk, -0.6), minFlux: threshold * riverLod(kk) }
  ```
  `riverLod(k) = Math.max(1, 4.5 * Math.pow(Math.max(1, k), -1.3))`（`common.ts:405`）。
- `shownRivers(rivers, threshold)`（`common.ts`）负责"全图不画小溪、放大才出现"的过滤；`world.rivers` 的元素是 `{ pts: Float32Array (x,y,flux 三元组), cells: Int32Array, drawn? }`（`src/gen/world.ts`）。

在查看器里的接法（推荐）：

1. 底图/瓦片保持"无河"（现状就是无河，正好）。
2. 服务端把 `world.rivers` 以 JSON 返回，前端每帧按当前 `k` 现画：
   - 新增 `GET /api/map/rivers?worldId=` → `{ threshold, wrap, rivers: [{ pts: number[], cells: number[] }] }`；
   - `mcp/viewer/vec-draw.js` 里照搬 `common.ts:480-520` 的循环（相邻顶点中点做端点、顶点做控制点、`lineWidth = widthOf(f)*lodTaper(style,f)*s`、画布外加 pad 跳过），颜色/线宽用上面那张风格表；
   - 河随缩放变粗、小溪按 `minFlux` 出现、河口不过海——和原版同一套数。
3. 需要"由矢量河反推影响地块"时，**不用自己算距离**：`River.cells` 就是河道经过的地块链（`src/gen/world.ts` 的 `River` 注释：从源头到入海/入湖处，首尾是湖/海地块与相邻地块的中点）。直接 `new Set(river.cells)`；太小的河用 `shownRivers` 同一门槛过滤。
   - 这份集合之后喂人口/商路/边界逻辑（影响什么见 Q3）。

验收标准：同一视角下 100% / 400% / 1200% 的河**走线完全相同**，只是线宽随 k 变化；河里不出现孤立短棒；河口停在海岸墨线上。

### 7.2 疆域：逐像素归属 + 州界国界，而不是盖方块

上游的疆域是"**每个像素属于哪个州**"算出来的，不是矢量多边形，也不是盖方块：

- `src/render/civ/territory.ts:126` `export function pixelRegions(mesh: Mesh, raster: Raster, regionOf: Int32Array, weak?: Uint8Array): Int16Array`
  - 输入：`world.mesh`、`raster`（2048×1024 的 `Raster`，带 `cell`/`water`）、`regionOf`（cell→州，就是 `civ.regions.of`）。
  - 输出：每个像素的州 id，**水 = −1**；海岸细节像素借相邻陆地块的州（`weak=1` 标记不可靠）。
  - 这一条就同时解决了"越海"和"海岸线不齐"。
- 上色：`civ.polity[region]` → 国家色；原版在水彩风下是"沿边界浓、往里淡 + 纸纹"，写实风是"淡罩染 + 贴边色带"，做法在 `territory.ts` 的 `washPixels` 一族；沙盒里可以先做**平涂 + 贴边加深**，够用。
- 国界：`src/render/civ/borders.ts` 的 `borderLines(civ, …)` / `bandLabels(...)`；原版国界是墨色虚线（手绘风）/细线（写实风），并且用 `bandLabels` 把"色块边"和"画出来的界线"对齐。
- 点击选国：`renderOwnerMap` 里那张 240 宽的 `grid` 可以保留，只用于命中测试，不再用来上色。

落地步骤（建议）：

1. 在 `mcp/viewer.ts` 里把 `renderOwnerMap` 的 `stampCells` + 三角形两段删掉，换成：
   ```ts
   const regionOf = Int32Array.from(civ.regions.of);      // cell → region
   const pr = pixelRegions(world.mesh, raster, regionOf); // 每像素州，水=-1
   // 再按 civ.polity[region] 填色，alpha 由风格决定
   ```
   注意 `raster` 要是和输出同尺寸（`rasterize(world, 1, false)` 就是 2048×1024）。
2. 边界加深：对每个像素看 4 邻域是否换了国，换则加一道深色（或直接叠 `borderLines` 的线）。
3. 想更接近原版：把 `territory.ts` 的 `washPixels` 纯函数直接 import 进来（它不碰 DOM，`stress` 脚本就在 Node 里跑它），只是它依赖 `CivDrawParams`（style/year/show），需要构造一个最小参数对象。
4. 验收：海岸线上不再有色块；同一国的色块连成一片；国界是一条连续的线，且**落在州界/山脊/河上**；放大到 400% 不出锯齿方块。
