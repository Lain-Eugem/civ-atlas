# civ-atlas 小事件裁决层（Petty Event Resolver）方案 v1

> 状态：等待确认后再写代码。
> 目标：把「不涉及君主战略」的微观判定交给本地 OpenJev，降低 DM 的 token 与决策负担；OpenJev 只返回概率，确定性抽样与效果落地仍由引擎/编排层负责。

## 0. 落点与边界（先定架构）

- **不改引擎推演循环，也不在 Worker 里发 HTTP**。现有引擎是同步、确定性、离线的；HTTP 决策放在已有“回合暂停”的编排层（`mcp/monarch.ts`、`mcp/dm.ts` 这一层），与现有 DM/君主调用同级。
- 每个回合的小事件按：**扫描事件 → 上下文预算打包 → 串行队列问 OpenJev → 确定性抽样 → 效果落地（命令/事实）→ 再进 DM**。
- 确定性底线：OpenJev 返回的是概率；抽样用引擎同一套种子派生工具（`subSeed` + `mulberry32`，`src/gen/util.ts`），salt 用 `事件ID + 回合数 + 国家ID`；抽样结果与原始概率都写日志，回放以“已结算结果”为准。
- 与现有代码的接口：`Session` 增加可选的 `petty` 状态；`monarchRound()`/`dmRound()` 在收集 DM 输入之前调用 `resolvePettyRound(session)`；工具层加 `civ_petty_setup/status/round`。

## 2. 任务三：ContextBudgetManager（含 estimateTokens）

### 2.1 estimateTokens 实现草稿

```ts
// 保守估算：中文/全角标点 1 token；英文数字 4 字符 ≈ 1 token；
// JSON 结构符号 { } [ ] " : , 每个 1 token；空白按 0.25；最后 ×1.1 向上取整。
const CJK = /[\u3400-\u4dbf\u4e00-\u9fff\u3000-\u303f\uff00-\uffef]/;
const ASCII_WORD = /[A-Za-z0-9]/;
const JSON_PUNCT = /[{}[\]":,]/;

export function estimateTokens(text: string): number {
  let raw = 0;
  for (const ch of text) {
    if (ch === '\n' || ch === '\r') raw += 0.25;
    else if (JSON_PUNCT.test(ch)) raw += 1;
    else if (CJK.test(ch)) raw += 1;
    else if (ASCII_WORD.test(ch)) raw += 0.25;
    else raw += 0.5; // 半角标点等，保守计
  }
  return Math.ceil(raw * 1.1);
}
```

### 2.2 ContextBudgetManager 接口

```ts
export interface PettyQuestionWire {
  type: PettyPrimitive;
  instructions: string;
  criteria?: Record<string, string>;
  options?: { id: string; label: string }[];
}

export interface PettyBatch {
  batchId: string;                                  // `${sessionId}:${round}:${n}`
  priority: PettyPriority;
  state: string;                                    // 模板渲染出的自然语言环境描述
  questions: Record<string, PettyQuestionWire>;     // key 用短名（trade_raid），省 token
  eventIds: Record<string, string>;                 // 短名 → eventId
  estimatedTokens: number;
}

export interface TokenReport {
  budget: number;          // 4250
  target: number;          // 4000
  envTokens: number;
  envP0: number; envP1: number; envP2: number;
  questionTokens: number;
  totalTokens: number;     // 单批最大估算
  packed: number;          // 实际打包问题数
  dropped: number;
  p0Complete: boolean;     // 必须恒 true
  perQuestion: { eventId: string; tokens: number }[];
}

export interface ContextBudgetManager {
  plan(events: PettyEventRequest[], opts?: { maxQuestionsPerBatch?: number }): {
    batches: PettyBatch[];
    report: TokenReport;
    dropped: { eventId: string; reason: 'no-budget' | 'throttled' }[];
  };
  estimate(text: string): number;
}
```

### 2.3 预算策略

1. 硬上限 `HARD = 4250`；目标 `TARGET = 4000`（留 250）。
2. 环境描述先占 `ENV_BUDGET = clamp(TARGET × 0.45, 1600, 2000)`（默认 1800）。
3. 环境描述按 **P0 → P1 → P2** 模板填充：P0 必须全含；P1 在超出 ENV_BUDGET 时从最后一项裁；P2 最先裁。
4. 剩余 `TARGET − envTokens` 打包问题：按优先级 P0→P1→P2、同级 FIFO；每批最多 8 个问题；装不下就开下一批。
5. 单个问题超预算且批为空时，允许单独成批；仍超 HARD 则丢弃并记录 `no-budget`（不裁 P0/P1）。
6. 每次请求前记录 TokenReport（P0/P1/P2 用量、问题数、总估算）到回合日志。

### 2.4 “8 个问题”预算计算示例

环境描述（L2，自然语言，约 100 个中文字符）：

> 第 247 年雨季，北河河谷平原（温带）。该地属大昌国，人口约 1.2 万，粮食储备 3200 单位，只够支撑到下一收获季。近三月降雨量低于常年六成；邻国边境最近有零星冲突。

- 该段 `estimateTokens ≈ 120`（118 中文字/全角标点 → 118，×1.1 ≈ 130，按 120–130 记）。
- P0 部分约 78，P1 约 30，P2 约 12（合计约 120）。

8 个问题（问题 key/instructions/criteria/options 一起估算）：

| 问题 | 估算 token |
|------|-----------|
| trade_raid | 168 |
| trade_profit | 156 |
| market_shortage | 150 |
| border_clash | 176 |
| ambush | 162 |
| riot | 154 |
| road_damage | 158 |
| public_works | 150 |
| **问题小计** | **1,274** |

请求外壳（model/state/questions 的 JSON 符号等）约 40。

**合计 ≈ 120 + 1,274 + 40 = 1,434 ≤ 4,250**，环境描述占比约 8%，远低于 45% 预留（说明常见情况 token 很宽裕；L3 且事实字段多时环境会长到 400–700 token，仍在上限内）。
若环境描述涨到 1,800（上限），剩余问题预算 = 4,000 − 1,800 = 2,200，仍可装 8 个问题（约 1,300），总 ≈ 3,100 ≤ 4,250。

## 3. 任务四：OpenJevQueue（严格串行）

### 3.1 接口

```ts
export interface OpenJevRequest {
  model: string;
  state: string;
  questions: Record<string, PettyQuestionWire>;
}

export interface OpenJevQueueStats {
  enqueued: number; completed: number; timedOut: number; failed: number;
  fallback: number; avgWaitMs: number; maxWaitMs: number; totalMs: number;
  maxInFlight: number;       // 验收用：必须恒为 1
}

export interface OpenJevQueue {
  enqueue<T>(task: {
    batchId: string; priority: PettyPriority; requestBody: OpenJevRequest;
    timeoutMs?: number;
  }): Promise<T>;
  runAll<T>(tasks: Array<{ batchId: string; priority: PettyPriority; requestBody: OpenJevRequest; timeoutMs?: number }>,
            deadlineMs: number): Promise<Array<T | { fallback: true; reason: string }>>;
  stats(): OpenJevQueueStats;
  inFlight(): number;
  reset(): void;
}
```

### 3.2 调度循环（分桶 + 单泵，简单可测）

```
buckets[10] = [], buckets[20] = [], buckets[30] = []   // 同优先级 FIFO
running = false
failures = 0
openUntilNextRound = false

function enqueue(task):
  push task into buckets[task.priority]
  if not running: pump()
  return promise

async function pump():
  if running: return
  running = true
  try:
    while any bucket non-empty:
      task = first non-empty bucket by 10 → 20 → 30
      if now - task.enqueuedAt > deadlineMs or openUntilNextRound:
        task.reject(FALLBACK_TIMEOUT); stats.timedOut++; continue
      inFlight++
      try:
        r = await fetch(endpoint, { method:'POST', body: JSON.stringify(task.requestBody),
                                    signal: AbortSignal.timeout(task.timeoutMs) })
        if !r.ok: throw HttpError(r.status)
        parse + validate probabilities; task.resolve(data); failures = 0
      catch e:
        failures++; task.reject(e); stats.failed++
        if failures >= MAX_FAILURES(5): openUntilNextRound = true
      finally: inFlight-- ; stats.maxInFlight = max(stats.maxInFlight, inFlight)
  finally: running = false
```

- 一次只起一个 `fetch`；`runAll` 用同一泵串行执行，不并发。
- P0 超时默认 60s，P1/P2 默认 30s；回合总 deadline 120s，超出部分全部走降级。
- 背压：待裁决事件 > 40 时，P2 直接降级/跳过（`throttled`）；回合结束前 `openUntilNextRound` 后剩余任务不再发请求。
- 熔断：连续失败 5 次 → 本回合后续全部降级；下一回合开始先 `probe`（发一个最小请求或 `/health`）一次，成功则清零恢复。
- 统计写入回合日志：入队/完成/超时/降级/平均等待/最大等待/总耗时/峰值在途。

## 4. 任务五/六：OpenJevResolver 调用流程（草稿）

```ts
export interface OpenJevConfig {
  enabled: boolean;
  baseUrl: string;              // http://127.0.0.1:3000
  endpoint: string;             // /v1/systemone
  model: string;                // openjev
  temperature: number;          // 显式固定，写日志/存档
  maxTokens: number;            // 4250
  targetTokens: number;         // 4000
  envRatio: number;             // 0.45
  maxQuestionsPerBatch: number; // 8
  timeoutMsP0: number;          // 60000
  timeoutMs: number;            // 30000
  roundDeadlineMs: number;      // 120000
  maxPending: number;           // 40
  maxConsecutiveFailures: number; // 5
  throttleP2: boolean;          // true
}

export interface PettyRoundResult {
  facts: PettyFact[];
  commands: Intervention[];     // 灾类等可落地命令
  report: TokenReport;
  queue: OpenJevQueueStats;
  fallbacks: { eventId: string; reason: string }[];
  throttled: string[];
  temperature: number;
  model: string;
}

export async function resolvePettyRound(
  session: Session,
  events: PettyEventRequest[],
  cfg: OpenJevConfig,
  bridge: { budget: ContextBudgetManager; queue: OpenJevQueue; client: OpenJevClient; apply(cmd): void },
): Promise<PettyRoundResult> {
  // 1) 背压：队列积压 > maxPending → 丢弃/降级 P2
  // 2) budget.plan(events) → batches（token 报告）
  // 3) queue.runAll(batches, roundDeadlineMs)  // 严格串行
  // 4) 每个成功批次：校验问题 key/概率；失败 → engineRuleFallback(mode)
  // 5) 确定性抽样：
  //    rng = mulberry32(subSeed(session.civ.seed, `petty:${eventId}`))
  //    choice/score：按归一化概率累计抽样；noul：rng() < pTrue
  // 6) 效果落地：kind='intervention' → cleanIntervention + 入命令表（from=当前年）；
  //    kind='note' → facts；未知/非法 → 跳过并记 fallback
  // 7) 写日志：petty-round-NNNN.json（含 token 报告、原始概率哈希、抽样结果、温度、耗时）
  return { facts, commands, report, queue, fallbacks, throttled, temperature: cfg.temperature, model: cfg.model };
}
```

- 失败降级：`engineRuleFallback(mode)` 按注册表 `fallback` 选最保守选项（用同一确定性随机流抽样），日志标 `fallback: engine-rule` + 原因。
- 连续失败熔断：队列层负责；下一回合 `probe` 恢复。
- 温度：`cfg.temperature` 显式写入请求/日志/`session.json`；文档注明换温度/权重=破坏确定性，需要重新校准。
- 原始概率与抽样结果都入日志：验收“概率分布逐位一致”直接比对两次请求的响应哈希；回放则用已结算结果（不重新问 OpenJev）。

## 5. 任务七：回合循环插入点与 DM 边界

```text
现有: monarchRound(s) / dmRound(s)
  1. 引擎扫描本回合待定小事件（registry 触发 + 快照事实）
  2. ContextBudgetManager 渲染环境描述、按预算打包/分片
  3. OpenJevQueue 串行执行（P0 → P1 → P2，超时/熔断降级）
  4. 裁决结果 → 确定性抽样 → 效果落地（disaster 命令 / 事实日志）
  5. 收集国家快照 + 小事件摘要（只给已结算事实）→ DM/君主
  6. DM 返回君主决策
  7. submitOrders([...pettyCommands, ...monarchCommands, ...dmCommands]) → turnStep
```

- DM 提示词**不暴露** OpenJev 概率、选项、置信度、队列信息；只看到“北方河谷发生轻度旱灾，粮食减产约 15%”这种已结算摘要。
- 若 DM 试图重新裁决已发生小事件，编排层忽略并提示“已由系统结算”。
- 小事件摘要要限长（如最多 8 条、每条 ≤ 40 字），避免把省下的 token 又加回 DM。

## 6. 测试与验收步骤

1. **token 合规**

   - 另抽 10 组把 state 文本落盘，人工核对 P0 四项（地区/国家、年份/季节、关键数值、触发条件）100% 出现。
2. **无并发**
